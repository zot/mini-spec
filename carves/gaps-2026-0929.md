# Carve: gaps 2026-09-29 — the instrument that says nothing when it did not look

> **DRAFT (Daneel, 2026-09-29) — for Bill to edit before its first part is worked.**

One shape runs through a cluster of open gaps in `tool/design/design.md`: **a check that
reports clean when it never looked, or a writer that produces a file its own reader cannot
fully read.** Each failure is well-formed and quiet, so it reads exactly like success. This
project names the principle often ("report absence as error, never as silence"); these are
the places the tool still violates it.

**Provenance.** Gap review with Bill, 2026-09-29, after a day on which the shape surfaced
twice: an alarm-puller's `-run` filter selected none of the tests guarding its alarm and came
back green (`O34`), and a resolved gap's unclosed two-backtick run hid a line of `design.md`
from its reader for thirteen days (fixed in place; see Item 2).

**The gaps stay the record.** Each part names the gap it discharges; the gap is resolved
when the part lands (`pending finish --resolve`), so `design.md` and this carve never hold
two open copies of one fact. Gaps left out on purpose: `O1`–`O5` and `O8` are hygiene and
test coverage, not this shape; `O21` is alarm tooling too, but it fails loudly
(`unresolvable`), which is the behaviour the rest of this carve is trying to reach.

## Items

**Item 1** (`O34`). `query alarms --brief` names test files and not tests, so the delegate
picks its own `-run` filter. Measured 2026-09-29: one of twelve re-pulls filtered to
`TestInit`, which matches none of the `TestRepair…` and `TestSetTrack…` tests guarding
`setTrack`, and returned a clean green; the same injection over the whole package failed
three tests. The fix removes the delegate's choice of filter rather than supplying a better
one.

### Item 1's decisions

**DECIDED (Bill, 2026-09-29): the brief does not name tests; it runs every test in the
alarm's directories, and the pull records which went red.**

- **Why not name them.** An alarm and its tests are many-to-many, measured on the day's
  pulls: Config #2's injection failed four tests, Init #2's three, Query #5's and
  CommitMessage #1's two each, while one test (`TestSelectImplementationAnswersEachRequirement`)
  went red for Query alarms 4, 5 and 6. The six `unanchored` alarms pin a document and have
  no site at all. A declared alarm→test field would be a hand-kept mirror of that relation
  with nothing checking it — `O7`'s defect in a new place — and would drift the first time a
  test is split or gains an assertion.
- **What the brief says instead.** Its `Directories:` line already lists every package
  holding one of the alarm's test files, across packages (CommitMessage's names both
  `internal/pending` and `internal/cli`). The brief directs `go test -count=1` over each of
  those directories with **no `-run` filter**, and asks for the names of the tests that
  failed as part of the evidence. A green over those directories is then a real result: the
  alarm did not ring.
- **The map comes free.** The `**Pulled:**` line records the tests that went red, so the
  alarm→test relation is measured on every pull and rewritten by every re-pull, current by
  construction instead of declared once.
- **The cost, accepted.** Whole-package runs took 0.5–2.6 s each on 2026-09-29, and their
  noise stays in the delegate's context, which is what delegating the pull is for.
